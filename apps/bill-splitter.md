# Bill Splitter

- Repo: [DangPham112000/bill-splitter](https://github.com/DangPham112000/bill-splitter). Live at `bills.dantepham.site` (`/opt/bill-splitter`) since 2026-10-25 (PR #4, DAN-84).
- Stack: pnpm monorepo; frontend React 19 + Vite + Tailwind + Apollo Client; backend Express + Apollo GraphQL + Mongoose; `shared/` holds money helpers used by both (VND by default, also THB, CNY, ...).
- Splits costs for a trip, project or party. Members join through a link without signing in; the app works out who pays whom with the fewest transfers.
- Sign-in: optional, with the shared Clerk app (live since 2026-10-25, DAN-84). The backend puts the Clerk user id in the GraphQL context as `clerkId` (null for anonymous members); no User table. Email, name and avatar come from `core.users` with a Clerk API fallback (`backend/src/coreUsers.ts`, DAN-93, bill-splitter #6); `me` returns `{ clerkId email name avatar }`. `Splitter.adminUserId` and `Member.userId` hold Clerk user ids, assigned once the create and join APIs exist (DAN-35, DAN-41). `CLERK_AUTHORIZED_PARTIES` is `${shared.prd.CLERK_AUTHORIZED_PARTIES}` (every ecosystem app, 2026-10-26).
- Secrets: Doppler `bill-splitter/prd` references `${shared.prd.CLERK_*}` and `${shared.prd.VPS_*}`; GitHub keeps only `DOPPLER_TOKEN`.
- Splitters (DAN-35, bill-splitter #7, 2026-10-26): GraphQL `createSplitter(input)` needs sign-in and makes the caller admin (`Splitter.adminUserId` = Clerk id, plus an admin `Member` linked by `userId`); input is name, type, coverEmoji, startDate/endDate as `YYYY-MM-DD`, currency (ISO 4217, VND default), hasInitialFund, adminName, memberNames. `updateSplitter` is admin only; `mySplitters` and `splitter(id)` return only splitters the caller administers or is linked to. `inviteToken` is shown to the admin only.
- From Event Manager (DAN-96, bill-splitter #8, 2026-10-26): `createSplitter` also takes `description`, `eventManagerEventId` and `linkedMembers [{ name, clerkId }]` (each must be an attendee of that event; they become members linked to that account). `Query.eventManagerEvents` lists the user's events, read live from Event Manager (`EVENT_MANAGER_GRAPHQL_URL`, default `http://event-manager-backend:4000/graphql`). A splitter keeps `linkedEvent { app, id, url }`. `/new?event=<id>` opens the create form with that event picked. `splitterForEvent(eventManagerEventId, timeZone)` (page `/events/<id>`, Event Manager's "Split costs" button) returns the event's splitter or creates it; one splitter per event.
- Device identity (DAN-30, bill-splitter #9, 2026-10-27): members don't sign in, so edit rights are bound to a device. Each browser keeps a random `deviceId` in localStorage and sends it as `X-Device-Id`; `registerDevice` also keeps it in an httpOnly cookie (`bs_device`) and restores it when localStorage is cleared (Safari wipes it after 7 days). Label such as "iPhone · Zalo" from the user agent, plus an optional nickname asked when someone first joins on that device (DAN-41). The API never returns another device's `deviceId`. Bill Splitter only: other apps calling it (DAN-94) send no device id, which is fine for `createSplitter`.
- Target of the data-sharing flow Journei → Bill Splitter (DAN-94, can call `createSplitter` with the user's session token and `memberNames`; `linkedMembers` only accepts attendees of an Event Manager event for now).
- MongoDB: database `bill-splitter` on the shared `ecosystem-mongo` (user `bill-splitter`, DAN-90, bill-splitter #5), started empty. See [infra/mongo.md](../infra/mongo.md).
- UI (bill-splitter #14, 2026-11-10): mobile-first redesign inspired by Tricount's structure (splitter list, Expenses / Balances / Members tabs; a sidebar and two columns on desktop), using the shared ecosystem theme (see decisions.md, 2026-11-10). Since bill-splitter #23 (2026-11-12) the surfaces are "liquid glass" (see decisions.md, 2026-11-12).
- Joining (DAN-41, bill-splitter #17, 2026-11-11): anyone with the join link `/join/<token>` picks a name or adds one without signing in; the pick is bound to the device (`X-Device-Id`), which can then open the splitter. A signed-in joiner can link the name to their account (`Member.userId`). Roles still need sign-in. Nothing changes for apps calling Bill Splitter (DAN-94): `createSplitter` still needs the user's session token.
- Planned (2026-11-11, Linear, not built yet). Parts other apps may care about:
  - Exchange rates (DAN-111): Bill Splitter's backend fetches daily rates from a free provider that lists VND (open.er-api.com; ECB/Frankfurter has no VND) and caches them in its own database. Another app needing rates (e.g. Journei trip budgets) should call Bill Splitter's `exchangeRate(from, to)` instead of adding a second provider.
  - Receipt OCR (DAN-116): the first ecosystem app calling an external AI API. Dang chose Gemini Flash (2026-11-12), paid from the monthly Google Cloud credits of his Google AI Pro plan, on the paid tier so receipts are not used for training. Credentials go in Doppler `bill-splitter/prd`, not `shared`; it runs in the existing Google Cloud project `yolo-ecosystem` (see [infra/google-cloud.md](../infra/google-cloud.md)). Photos are not stored.
  - VietQR (DAN-118, DAN-119): bank accounts are Bill Splitter data (saved per Clerk id in its own database, never in `core.users`); the QR payload is built in the browser, no third-party QR service.
